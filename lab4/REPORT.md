# Отчёт по лабораторной работе 4. Базовые растровые алгоритмы

## 1. Цель и архитектура
Реализовано веб-приложение на TypeScript (Vite). Рисование примитивов не используется: алгоритмы из `RasterEngine` только вызывают `IRasterTarget.setPixel(x, y, intensity)`, который заполняет `VirtualGrid` (массив `Float32Array`). `GridPainter` потом рисует по массиву увеличенные клетки, линии сетки, оси и подписи.

Реализовано: пошаговый алгоритм, ЦДА, Брезенхем (линия, все 8 октантов), Брезенхем (окружность, симметрия по 8 октантам), алгоритм Ву (интенсивность = доля покрытия), целочисленный алгоритм типа Питвея для эллипса/конического сечения.

## 2. Привязка целочисленных координат к сетке
Целая точка (x, y) — центр клетки. Клетка покрывает [x−0.5; x+0.5]×[y−0.5; y+0.5]. Начало координат — центр центральной клетки, ось Y направлена вверх. Округление `floor(v+0.5)`. В интерфейсе: масштаб (колесо/ползунок), сдвиг, линии сетки по границам клеток, подписи осей, отображение клетки под курсором.

## 3. Теория
**Пошаговый:** y = y0 + k(x−x0), k = dy/dx, на каждом шаге умножение и округление; при |dy|>|dx| роли осей меняются.

**ЦДА:** L = max(|dx|,|dy|); xi = dx/L, yi = dy/L; на каждом из L+1 шагов: две сложения во float и два округления.

**Брезенхем:** ошибка err = dx + dy (dy<0), на шаге e2 = 2·err; если e2 ≥ dy — шаг по x, если e2 ≤ dx — шаг по y. Знаки шагов sx, sy выбираются по направлению, поэтому одна форма работает во всех 8 октантах без перебора случаев.

**Окружность (средняя точка):** x=0, y=R, d=3−2R. Если d<0: d+=4x+6; иначе d+=4(x−y)+10, y−−. Строится 1/8 окружности, остальное — по симметрии.

**Ву:** на ведущей оси на каждом шаге вычисляется y; пиксели (x, ⌊y⌋) и (x, ⌊y⌋+1) получают интенсивности 1−frac(y) и frac(y). Это и есть α для смешивания с фоном.

**Питвей (эллипс):** F(x,y)=b²x²+a²y²−a²b². Решающая переменная в точке средней между двумя кандидатами; умножением на 4 убираются дроби, все приращения целочисленные. Две области (наклон меньше/больше 1), симметрия по 4 квадрантам.
Примечание: в литературе «алгоритм Кастла–Питвея» также связывают с применением алгоритма Евклида для отрезков; здесь реализован вариант для конических сечений, как требует задание.

## 6. Почему ЦДА медленнее Брезенхема
Время растеризации линейно по длине: T ≈ c·L, различается константа c.
- **ЦДА** на каждом шаге: 2 сложения с плавающей точкой, 2 округления (floor(v+0.5) с преобразованием double→int), плюс накопление ошибки округления (xi, yi — неточные двоичные дроби). Предварительно — 2 деления.
- **Брезенхем:** на шаге 1–2 целочисленных сложения, сдвиг (2·err), 2 сравнения; без делений и округления, ошибка не накапливается.
- **Пошаговый:** умножение и округление на шаге, то есть ещё дороже ЦДА по операциям, но без накопления ошибки.
- **Ву:** примерно вдвое больше записей в растр (2 пикселя на шаг) и вычисление floor/frac.

Нужно честно учесть: в JavaScript все числа — double, а JIT оптимизирует целочисленные операции, поэтому разрыв между ЦДА и Брезенхемом на современном железе может быть небольшим (десятки процентов), а не кратным, как в C/C++ на старых процессорах без быстрого FPU. Кроме того, при коротких отрезках заметную долю времени занимает вызов `setPixel` (проверка границ, запись в память), общий для всех алгоритмов. Поэтому выводы нужно подтверждать графиками «время от длины»: наклон прямой у ЦДА должен быть больше, чем у Брезенхема. Если у вас получилось иначе, это нужно объяснить (JIT, кэш, доминирование setPixel) и не подгонять результат.
