# Лабораторная работа №2 — React + Rust + wasm-bindgen

Приложение для локального чтения метаданных PNG, JPEG, GIF, BMP, классического TIFF и PCX. Rust вручную разбирает байты. React отвечает за интерфейс, JS — за выбор файлов, чтение диапазонов и пул Web Workers. Серверная часть не нужна. Файлы не отправляются в сеть.

## Важно о готовности

Это исходный проект, а не заранее собранный dist или EXE. При подготовке архива проверен синтаксис обычных JS-файлов через `node --check`; контрольные неповреждённые изображения открывались независимым декодером. В среде подготовки отсутствовали Rust и wasm-pack, поэтому сборка Rust/WASM, JSX и запуск Playwright здесь не выполнялись. Перед сдачей обязательно выполните сборку, тесты и проверку на архиве преподавателя. Самого архива «Для проверки Lab#2» у нас нет. Нельзя обещать 9–10 баллов без этой проверки.

Программа проверяет структуру, а не декодируемость всех пикселей. Подробности и ограничения — `docs/ARCHITECTURE.md` и `docs/FORMAT_REFERENCE.md`.

## 1. Установка инструментов (Windows)

Нужно:
- Node.js 22 LTS с npm.
- Rust stable, версия не ниже 1.85, установленный через rustup.
- Для стандартного Rust Windows MSVC toolchain — Build Tools for Visual Studio, компонент C++ build tools / Desktop development with C++ и Windows SDK. Установщик Rust может предложить это сам.
- Браузер с WebAssembly и module Web Workers; для основного сценария выбирайте актуальный Chrome или Edge.

Откройте новый PowerShell после установки:

```powershell
node --version
npm --version
rustc --version
cargo --version
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
wasm-pack --version
```

Если PowerShell блокирует npm.ps1, используйте `npm.cmd` вместо `npm` в командах (не требуется отключать политику безопасности). Если wasm-pack не найден, перезапустите терминал и проверьте, что каталог Cargo bin находится в PATH.

## 2. Первый запуск

Распакуйте архив и перейдите в папку, где находится package.json:

```powershell
cd image-lab-react-rust
npm install
npm run wasm
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://localhost:5173`.

`npm run wasm` запускает:

```text
wasm-pack build ./rust --target web --release --out-dir ../public/wasm
```

`--out-dir` считается относительно Rust crate: выходные файлы попадут в корневую `public/wasm`. Там будут `image_meta.js` и `image_meta_bg.wasm`. Worker загружает их как обычный браузерный ES-модуль. Специальный Vite-плагин для WASM не нужен: WASM находится среди статических ресурсов, а не импортируется из графа бандлера.

После изменения Rust выполните `npm run wasm` ещё раз и перезагрузите страницу. Изменения React подхватываются Vite автоматически. При первом запуске нужен Интернет для загрузки npm/Cargo зависимостей; обработка выбранных изображений работает локально.

## 3. Пользование

1. «Выбрать папку» — рекурсивный обход. Если showDirectoryPicker недоступен, используется input с webkitdirectory.
2. «Выбрать файлы» — несколько файлов любого расширения.
3. Выберите число Workers: стартовое значение до 4, можно 1–8.
4. Дождитесь завершения; можно остановить обработку. Уже прочитанные строки остаются.
5. Поиск работает по пути и формату. Фильтр выделяет повреждённые, неподдерживаемые файлы и строки с замечаниями.
6. Нажмите строку, чтобы увидеть источник характеристик, замечания и статистику чтения.
7. CSV экспортирует текущую отфильтрованную выборку.

Лимит — 100000 файлов. Неизвестные типы тоже получают строку: приложение не отбрасывает файлы только по расширению. Если текстовый файл назван .jpg, он отмечается повреждённым. Если настоящий PNG переименован в .jpg, приложение определяет PNG и сообщает о несовпадении.

DPI отсутствует в файле — выводится «—», а не выдуманные 72 или 96. GIF не имеет абсолютного DPI. Размер GIF — логический экран, TIFF — первая страница. Глубина включает alpha/дополнительные samples там, где они указаны в формате; для палитрового изображения это глубина индекса, а не 24 бита RGB палитры.

## 4. Тесты

```powershell
npm run test:rust
npm run wasm
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает dev-сервер. В `tests/fixtures` уже есть компактные файлы всех шести форматов, big-endian TIFF и повреждённые варианты. Устанавливать Python или Pillow для работы приложения и тестов не требуется. Pillow использовался только при изготовлении части контрольных картинок, никогда не в приложении.

Rust unit tests проверяют endian, выход за границы коротких полей, CRC32, сигнатуры и RATIONAL. E2E проверяет таблицу, геометрию, DPI JPEG/TIFF, повреждения, переименованное расширение, поиск и CSV. Это стартовый набор, не доказательство поддержки всех вариантов форматов.

## 5. Проверка быстродействия

Нужна собственная папка с примерно 600 JPEG суммарно около 2 ГБ. Если есть JPEG размером примерно 3–4 МБ, можно сделать копии:

```powershell
node scripts/make-benchmark.mjs "C:\images\large.jpg" "C:\images\benchmark600" 600
```

Для проверки количества, а не объёма:

```powershell
node scripts/make-benchmark.mjs "tests/fixtures/rgb.jpg" "C:\images\benchmark100k" 100000
```

Скрипт реально копирует файлы; убедитесь в свободном месте. Не дописывайте произвольный мусор для искусственного увеличения JPEG. Повторённые изображения подходят для нагрузки на обход и I/O, но не для проверки разнообразия парсеров.

Сравните Workers=1,2,4,8. Время в интерфейсе включает инициализацию Workers и чтение метаданных, но не выбор/обход папки. Сохраняйте отдельно время обхода при оценке полного сценария. Показатель «Считано» — сумма размеров JS диапазонов File.slice, не физический объём чтения диском. ОС и браузер могут кэшировать данные. Не заявляйте универсальное ускорение или число секунд без измерений на своём ПК.

## 6. Production-сборка

```powershell
npm run build
npm run preview
```

Обычно preview доступен на `http://localhost:4173`. Итоговая папка — `dist`, включая `dist/wasm/image_meta.js` и `dist/wasm/image_meta_bg.wasm`.

Нельзя запускать через двойной щелчок по dist/index.html (file://): модулям, Workers и WASM нужен HTTP-сервер.

## 7. Публикация — простой вариант Netlify

1. Выполните `npm run build` локально.
2. Войдите в Netlify и откройте раздел ручного деплоя/Drop.
3. Перетащите именно папку `dist`, не исходную папку и не только index.html.
4. Получите публичный HTTPS URL и проверьте выбор папки на нём.
5. Для обновления повторно соберите и загрузите dist.

В этом сценарии Rust не нужен на хостинге: вы загружаете готовую статику. Сервер/API, Docker, база данных и COOP/COEP не нужны. Используется несколько независимых WASM экземпляров в Workers, а не разделяемая память WASM threads.

Другой статический HTTPS-хостинг тоже подходит. Все содержимое dist должно сохранять относительные пути. Сервер должен отдавать .wasm как application/wasm и .js как JavaScript. Если хостинг возвращает HTML вместо /wasm/image_meta.js, исправьте маршрутизацию или путь.

## 8. Публикация в подпапке

При размещении по адресу https://host.example/lab2/:

```powershell
$env:APP_BASE="/lab2/"
npm run build
Remove-Item Env:APP_BASE
```

Разместите dist в /lab2/. Для Linux/macOS аналог: `APP_BASE=/lab2/ npm run build`.

Для публикации в корне APP_BASE не нужен. Пути к Worker/assets задаёт Vite, к WASM — import.meta.env.BASE_URL.

## 9. Если что-то не работает

- WASM не найден: сначала npm run wasm; в Network проверьте image_meta.js и image_meta_bg.wasm, их HTTP статус и содержимое.
- Worker fatal: смотрите Console; проверьте module script MIME type, BASE_URL, CSP и отсутствие HTML fallback для wasm/js.
- showDirectoryPicker отсутствует: используется резервный выбор папки; лучше актуальный Chrome/Edge. Публичная страница должна быть HTTPS.
- Сообщение при чтении: права на файл, удалённый/перемещённый файл или нестандартный заголовок. Приложение не должно падать от одной ошибки.
- Высокое число Workers медленнее: уменьшите число потоков; HDD и системный кэш меняют результаты.
- BigTIFF/нестандартный OS/2 BMP: статус «Не поддерживается», это не утверждение о повреждении.
